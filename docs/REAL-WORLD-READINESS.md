# CivicSignal deployment readiness

This repository contains a working report-to-staff workflow, but it is not configured for verified municipal boundaries or email/text delivery. Staff assignment uses administrator-configured municipality centers: the nearest eligible verified person in the report's municipality is chosen first; if nobody is available there, the closest eligible person in any organization is chosen. A cross-organization assignee is granted access to the assigned report, its photo, and its workflow actions. Account holders can opt in to browser push alerts on supported devices; the app does not substitute verified boundaries, fabricated staff coverage, or pretend messages.

## Configure the existing report workflow

1. Complete first-run setup to create the deployment administrator.
2. In Administration, create the real receiving organizations and issue categories. Each category is routed to the organization selected by the administrator. Municipality center records and organization municipality assignments are configured in the database; the Administration UI currently manages organizations and categories only.
3. Register staff accounts and verify each person into the correct organization. On submission, AI routes the classified report to that organization and assigns the nearest eligible verified person, preferring the report municipality and otherwise the closest eligible person in any organization. Staff in the receiving organization can act on its queue; a cross-organization assignee can also open, update, and see that assigned report in their queue.
4. Publish the operator identity, a verified organization contact route, applicable privacy terms, and a retention policy before inviting real residents.

When a resident submits a photo and GPS pin, CivicSignal sends the photo for classification, records the AI-written title and problem description, the selected category, receiving organization, assigned staff member, status, report history, and photo. A guest report returns a random access token once. The browser places it in a URL fragment so it is not sent with ordinary page or referrer requests; report and photo API reads require the token in a request header. The database stores only the token hash. Guest links expire after 90 days. The report and photo themselves are not automatically deleted.

Staff queues and report details show a workload priority when active reports for the same category cluster within 100 meters. `Standard` means one distinct reporter; `Elevated` means two or three; `High` means four or more. Only open, visible reports from the last 30 days are counted, and repeated submissions from the same signed-in account do not add a second reporter. Guest submissions count individually because the app cannot verify that two guest reports came from the same person. Priority is an internal corroboration signal, not a verified duplicate, emergency rating, or commitment to a response time.

The adapter contract in `server/jurisdiction.ts` is a typed seam only. No geocoder, boundary dataset, staff schedule, email/text sender, or municipal integration is bundled or claimed as operational. Gemini photo classification becomes available when a server key is configured, unless the disable switch is set; the public routing-readiness API and report form identify when it is unavailable. Classification is required: a report consists of a photo and GPS pin, and the server writes the title and problem description, selects the category and organization, and auto-assigns the nearest eligible verified staff member. Assignment can cross organization boundaries when the report municipality has no available staff, and the chosen assignee can open and work the report; it still does not verify legal jurisdiction or boundary polygons.

## Privacy and safety checks before launch

- Keep photo storage private and verify provider-side settings, including legacy object migration.
- Confirm the receiving organization has an authorized staff account before routing real reports.
- Set a retention schedule and publish who operates the deployment and how residents can contact that operator.
- Keep the emergency warning visible. This service is not monitored for urgent response and is not a substitute for 911 or the receiving organization's urgent contact channel.
- Do not present a submitted report or an authorized status update as independently verified damage or completed government work.
